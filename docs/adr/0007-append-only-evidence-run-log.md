# Evidence check runs are logged append-only at the Project level

Evidence checks were stored only on the prepared sentence that ran them (#10), so editing a checked sentence — which rightly resets the sentence on re-preparation — silently erased the run, and no evidence trail could account for spent runs. We decided (issue #11) to also append every completed run to a Project-level `evidenceRuns` log: the sentence keeps the current check for display and decisions, while the log is the durable trail the Markdown export reads and the source for reopening an unchanged check without a new model call. The duplication is deliberate — the attached check is mutable working state, the log is the permanent record. Entries are never rewritten or removed; integrity against later edits is computed at read time by comparing the logged sentence text and source fingerprints against the live Project, not by flagging entries in place.
